# xnote UI Round 2 Implementation Plan

**Goal:** Make xnote a quiet, content-first desktop Markdown app while preserving existing filesystem and save behavior.

**Architecture:** Keep Electron / React / CodeMirror and the existing typed storage contract. Change presentational markup, global tokens and component styles; add only the interaction state needed for folder disclosure and compact navigation. Do not modify server, storage preferences, save queue or transport.

**Tech Stack:** Existing React + TypeScript, CSS, Lucide, CodeMirror 6, Playwright and Vitest.

## Current findings

- `src/styles.css` mixes tokens, shell, settings and responsive overrides. Small 8–10px text, boxed note rows and search, repeated metadata, shadowed toolbar pills and blurred modal backgrounds compete with content.
- `App.tsx` already connects all actual operations. Preserve handlers while adding folder disclosure, keyboard-reachable list actions and compact rail navigation.
- Width media queries force values using `!important`, overriding remembered widths and making drag interaction misleading.
- `NoteEditor.tsx` cleanly isolates CodeMirror and Markdown preview. Preserve source text and editor state; use conservative syntax decorations on inactive lines with an explicit source view.

## Design

Neutral light palette: #fff canvas, #f7f7f5 navigation, #f3f3f0 secondary surface, #292929 body, #858585 secondary text, #a0a0a0 tertiary, #eaeae7 separators. Muted orange is reserved for the mark, favorites and meaningful focus. Dark mode uses corresponding neutral grays rather than olive surfaces.

UI 13px with 11–12px supporting labels; title30px/600; default prose16px/1.7. Center document content at max800px plus responsive gutters. Navigation and note rows are flat, spacing provides grouping, selected rows use faint gray. Toolbar has transparent background with subdued controls, always keyboard accessible. Dialogs and menus share small radii, simple borders and low shadows. Empty state uses a simple brand mark without decorative illustration or slogans.

## Implementation sequence

1. Write focused Playwright interaction tests for collapsible folders, compact navigation, keyboard-accessible note menus, keyboard resizing and overflow in narrow/large windows. Agent owns `tests/ui.spec.ts`.
2. Replace global shell styles with cohesive tokens, spacing and responsive grid; extract settings/dialog styles into `src/components/settings.css` to prevent editor/global selector collisions. Main owns App, global CSS and shared settings styles.
3. Editor agent owns NoteEditor/editor.css and conservative source presentation with tests. Preserve TXT and all existing formatting/preview controls. Exact source remains accessible; no rich-text round trip.
4. Verify every major surface in real Chromium windows at860/1100/1440/1920px, light/dark, and compact sidebar; inspect screenshots of editor, preview, settings and menus.
5. Run all unit/filesystem tests, production build, existing real-file E2E and added UI tests. Verify protected modules match recorded hashes. Launch Electron and build updated distribution artifacts.
6. Save current UI screenshots and append results to a separate UI verification record.

## Scope controls

No new dependencies. No changes to file naming, storage format, save queue, root directory settings, migration or IPC. No full editor migration or generic component refactor. Folder disclosure and temporary layout/navigation state remain UI-only.
