# xnote UI Round 3 Implementation Plan

**Goal:** Polish the existing Typora-like three-column UI and repair Markdown input and formatting without changing file storage or dependencies.

**Architecture:** Retain React, CodeMirror 6 source editing, live Markdown decorations, react-markdown preview and Lucide. Keep storage, API, save queue, IPC and preference schema intact. Use browser-native caret/selection and layout-preserving syntax marks, shared visual tokens and container-based document gutters.

**Tech Stack:** Existing TypeScript, React, CodeMirror 6, CSS, Vitest, Playwright and Electron.

## Findings and design

- Global `font-synthesis: none` prevents synthetic italic for system Chinese fonts. Toolbar uses underscore emphasis, which is invalid within English words. Cancellation only recognizes a selection directly between identical delimiters.
- `drawSelection()` hides native caret and selection with high-priority CSS and draws an asynchronous overlay. Prefer native main selection for this single-caret prose editor.
- Replacing inactive syntax markers removes their width; exposing them on selection changes can rewrap text. Keep their layout width and hide only their ink.
- UI tokens currently include 11/13/30px; headings/code/preview introduce additional sizes, settings permit 18–28px, and Lucide icons use inconsistent dimensions.
- Document gutters are fixed at several breakpoints. Establish a single 800px content measure with clamp-based gutters; align header, toolbar and body. Unify list content insets and selected navigation color.

## Tasks

1. Add focused regressions in `tests/editor.test.ts` and new browser tests for inline emphasis, cancellation, paragraphs, caret/selection, toolbar state and layout. Run the new tests against the original code to confirm the failures.
2. Repair formatting in `src/components/NoteEditor.tsx`: parse existing Markdown ranges for toggling, use valid emphasis markers, preserve selection/focus, expose active toolbar state, handle prose paragraph/soft breaks while retaining list/code handling. Keep TXT input and raw Markdown storage intact.
3. Replace width-changing marker decorations in `src/components/markdownPresentation.ts`; use native caret/selection and scoped italic synthesis. Consolidate editor and preview typography in `src/components/editor.css`.
4. Update `src/theme.css`, `src/styles.css`, `src/components/settings.css`, `src/App.tsx` and `src/components/Settings.tsx`: restrict sizes, normalize Lucide, simplify brand/menu glyphs, establish responsive gutters, list alignment and quiet orange navigation selection. Retain existing resizing/navigation handlers.
5. Run Vitest, TypeScript/build and all real-file browser E2E tests using isolated temporary storage. Verify protected business modules with SHA-256. Exercise actual browser/desktop UI, capture light/dark/edit/preview/settings/narrow/wide screenshots and inspect them.
6. Record verified results and practical boundaries in `docs/ui-round3-verification.md`. No distribution rebuild is required beyond the existing application build.
